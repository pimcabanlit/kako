How Kako uses Meko

Every part of Meko's context, followed through one household: the Villanuevas, from August to December 2026.

Meko's own docs ↗

Kako is a planner for a household's money. Mara and Jun talk to it in planning sessions; an orchestrator and four specialists answer; an engine works out every peso. Meko is where Kako keeps the household's context: what was said, what was learned, what every agent can find, and the trace of how each answer was reached. Postgres keeps the exact numbers. This page shows how each part of Meko's context is used, with the moment in the Villanuevas' story where you can see it.

On this laptopThe sandbox runs with Meko switched off (KAKO_MEKO_OFF), so new questions there are kept in Kako only. Everything below describes Kako against Meko: local Meko in development, Meko Cloud for the demo.

The household's datapack

The Villanuevas have one datapack. Every call Kako makes names it with datapack_id, and every agent speaks as itself: kako:orchestrator, kako:debt, kako:savings, and so on. It holds:

Isolation

  • One household, one datapack. Nothing from another household can reach the Villanuevas' answers, and every call carries their datapack_id.
  • Local first. Development and tests use local Meko on 127.0.0.1. Meko Cloud is reached only for the demo, and a call counter stops each Free-tier tool at a ceiling so rehearsals can't use up the lifetime allowances.
  • Agents by name. Each agent writes and deletes only its own memories, which Meko enforces.

Conversations built

Each planning session is one Meko conversation. When Kako answers a turn, it adds the household's words, Kako's reply, the plan (the steps taken: the brief, the specialists asked, the reconciliation, the options) and the reasoning (the specialists' summaries), with metadata naming the plan, run and recommendation. After the session, dreaming reads the turns back from Meko.

In the story · Session 2, Sep 15Mara asks how hard to pay down the card; Jun wants ₱4,000 extra and the rest to the emergency fund. The turn kept in Meko carries both specialists' proposals, the conflict, and options A and B. That same conversation is what dreaming reads later.

Decision traces built

The conversation id is the trace. Every Meko call in a session (the brief's search, a specialist's extra search, the turn being kept) is a step under it. Each recommendation in Kako has an Open trace link: to Meko Cloud's Observe for the demo, or to local Meko's call log, read back by GET /api/v1/sessions/{id}/trace. Kako also counts every call in its own table, so the trace and Kako's records always agree.

In the story · Session 4, Nov 20Jun's "what does it change?" is answered as a replan. Its trace shows the one search the brief made, what came back, and the turn kept with "what changed" and "why".

Memory built

Kako writes one sentence to Meko for each fact, decision and preference a person approved, naming people and things in full because Meko's search favours named entities. When a fact is replaced, its sentence is rewritten in the past tense; when one is withdrawn, its memories are deleted. Meko also extracts memories from the household's words on its own. Kako treats those as candidates: each ends linked to a fact a person approved, or deleted.

In the story · Nov 20 → Dec 1After Mara approves her new job, "Mara Villanueva's take-home pay is ₱52,000 a month" becomes "…was ₱52,000 a month", and a new memory says ₱68,000 from Dec 1. Meko keeps both; Kako's ledger says which one is true today.

Dreaming runs once after a session ends. It reads the turns and Meko's candidate memories, checks every claim in code (the quote is real, every number is in the quote), and puts proposals in front of the household. Across sessions, code counts the options the household chose: three the same way across at least two sessions make a pattern. Promotion is asked twice, because it can't be undone.

In the story · Oct 20Sessions 1, 2 and 3 (Aug, Sep, Oct) each chose the option that keeps cash on hand. Dreaming proposes the preference for flexibility; Mara approves it, Jun confirms sharing it and Session 1's decision record. In Session 4 the debt specialist cites the preference though nobody mentions it.

Knowledge base built

The household's documents go to the datapack's knowledge base: the monthly statements for the card, the car loan, the emergency fund and savings; Kako's planning rules; and Philippine reference documents on 13th-month pay, SSS, Pag-IBIG and emergency funds. A decision record promoted from dreaming lands here too. Each turn's brief makes one context_search, which covers memories, the knowledge base and past conversations together, and cited passages show in the plan's "why".

In the story · Session 4, Nov 20When Jun asks what Mara's new job changes, the one search can bring back the November statements, the 13th-month pay reference and Session 1's decision record ("keep a bigger buffer"), promoted to shared knowledge on Oct 20.

Self-learning built

Meko logs every context_search with how well it scored. Kako turns weak searches (best score under 0.75) into plain questions for the household ("Kako would like to know…"). Once an answer is approved and its memory is in Meko, Kako replays the search (selflearning_verify) and keeps the score before and after for the Metrics page. Meko Cloud only: local Meko has no self-learning tools.

Artifacts planned

Each plan report will be kept whole as a Meko artifact, its hash stored with the plan, so the report the household accepted can be fetched later exactly as it was, and downloaded from the Plan screen.

Postgres in the datapack planned

The household's facts (dated, never overwritten) live in plain Postgres today. The plan is to keep them in the datapack's own Postgres (AMP), next to the rest of the context. A Phase 1 test ran Kako's migrations and health check against AMP from this laptop; what-ifs stay in the engine in memory, because a Free account's compute can't query a branch.

Sharing and collaboration in part

Mara and Jun share one household datapack. Either can speak in a session, and each approves the other's changes: every fact, decision, preference and promotion waits for an adult's yes. Promotion is how something one session learned becomes context every agent shares.

In the storyMara chooses the split in Session 2; Jun accepts plan v3 on Dec 1; Mara approves the preference and Jun confirms sharing it.
Not pursuedEach adult's private memories next to shared household knowledge needs Meko's roles (Viewer, Contributor, Maintainer) on a paid plan. Documented as the production path.

Metrics built

The Metrics page reads Meko's datapack_metrics: how big the household's whole context is, how much one search saves sending, and how relevant results were. Next to it, Kako's own figures: each turn's brief against the whole context, its model calls, tokens and cost.

The rule of thumb: Postgres knows what is true; Meko knows what was said, what was learned, and how each answer was reached. Meko can hold "₱52,000" and "₱68,000" side by side; Kako decides which one is current and which decisions rested on the old one.
